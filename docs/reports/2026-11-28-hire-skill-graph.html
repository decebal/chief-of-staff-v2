PR #66 · chief-of-staff-v2 · 2026-11-28

A hire now runs with the skills you chose for its role, and the ones you marked irrelevant stay out of its session.

For the user hiring Claude Code and Codex agents through cos agents. You mark each skill on the machine relevant or not, say which roles use it and what it needs; every hire then loads exactly that set, and the dialog and run page show it. Design: hire skill graph.

01 / Before and after

Before, a hire saw every skill on the machine; now it sees its set.

Before 2e295db

src/agents/harness.rs argv (Claude)
claude "<prompt>" --permission-mode acceptEdits
  --settings '{"sandbox":{…}}'
every ~/.claude/skills entry, relevant or not, in the session
Codex: all 321 skills on this machine listed

After PR #66 head

src/agents/harness.rs argv (Claude)
claude "<prompt>" --permission-mode acceptEdits

Codex: -c skills.config=[{name="…",enabled=false},…]

02 / What a person actually sees

Real Claude loads the bundled skill and drops the hidden one.

03 / Prove it yourself

Mark one skill irrelevant, then watch a planned hire switch it off.

1

See what is left to decide.

cos skills ls --unreviewed

Pass: one line per skill under your skill roots, each unreviewed, its roots in brackets. If Prime is not answering, a note: line says so and the list still prints.

2

Record one decision. This writes to your Prime.

cos skills set seo-audit --irrelevant

Pass: recorded seo-audit on stderr, exit 0; cos skills ls now shows seo-audit irrelevant. Use a skill name from step 1 if you have no seo-audit.

3

Plan a hire without starting it.

cos --dry-run agents spawn --role builder --prompt "Implement the cache" --repo ~/Projects/founder-mode/chief-of-staff-v2

Pass: the printed plan has a skills object whose hidden list holds seo-audit; graph.state is stale (a dry run reads the cached graph, never Prime).

4

The same from the window.

Chief of Staff → Agents → Skills: the skill sits under Irrelevant. Hire → pick Builder → the Skills section under the contract lists the picked skills with why each is there.

Pass: marking a skill Relevant with a role chip moves it, and the next plan in the hire dialog picks it with "its role".

04 / Traps

A skill that still loads is not always this change failing.

SymptomIts tellWhat it actually is
An irrelevant skill still loads in a Claude hireIt comes from an installed plugin (name:skill), not ~/.claude/skillsPlugin skills are out of scope; the plan warns "skills from installed plugins still load".
A hidden skill is listed anywayThe hire's repo has its own .claude/skills/<name> or .agents/skills/<name>Repo skills win by design and are never hidden.
The plan's graph is stale or noneA Prime did not answer warningPrime is down or slow; the hire runs on the last graph read. Prime is asked at most once per 30 s.
A Codex hire refuses to start, naming config.tomlYour $CODEX_HOME/config.toml does not parse or cannot be readIntended: running on would re-enable skills you switched off there.

05 / What this proves that the tests cannot

The tests drive stand-ins; only a live run shows the harnesses obey the flags.

Every cos test runs against a stand-in Prime (tests/common/prime.rs) and a stand-in Herdr, and asserts the command line cos builds. None shows that Claude loads a --plugin-dir outside its working directory, that skillOverrides removes a skill from its listing, or that Codex honours a per-invocation skills.config. The live runs above settle those three. The live Prime was read twice, read-only: prime_search returns the shape the stand-in serves; tools/list shows the input schemas the stand-in accepts and no output schema for prime_add_node.

Gates at the PR head: task test (fmt, clippy -D warnings, 46 test binaries, 0 failures), task desktop-check, and the desktop suite. Reviews: three design rounds, three code reviews (the repo's prove-it), three rounds on the design's "Built as" section; every review file sits beside the design.

06 / Limits

What I have NOT checked.

  • A full hire launched by cos in the real Herdr with the real Claude or Codex: the live checks drove the harnesses directly with the flags cos builds.
  • The Skills pane, hire dialog section and run page fold as rendered: no screenshots (see the capture gap).
  • The reply shape of a real prime_add_node: no write was made to the live store. If it carries no id, the fact is recorded and its requires edges are skipped with a warning.
  • Whether a skill Codex switched off can still be invoked by name, and any Codex version but 0.172.0.
  • Prime sync is off on this machine; facts written here do not reach the AllSource dashboard.
  • Linux: every run here was macOS.
