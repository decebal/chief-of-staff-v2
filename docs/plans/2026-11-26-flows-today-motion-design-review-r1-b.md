1. blocking Today > Hires inbox, sessionStorage: report keeps per-id boxes in `sessionStorage` so cards glide across reloads. The report frame is sandboxed without `allow-same-origin` and has an opaque origin, so storage access throws. Evidence: apps/desktop/ui/index.html:196 `sandbox="allow-scripts allow-popups"`; apps/desktop/ui/app.js:232 "no storage of its own (sandboxed, opaque origin)". Fix: drop cross-reload glide or carry last positions through the host (`cos-host` / parent postMessage) instead of storage; state that the report script has no storage and wrap any storage access in try/catch. Acceptance 3 (glide across reloads) depends on this.

2. should Today > Brief loader: design adds a new `{type: "cos-host", briefRunning}` message and calls it "the same channel as runBrief". A brief-state channel already exists: the window posts `cos-brief-state` with `state: "running"` and text, and the report handles it. Evidence: apps/desktop/ui/app.js:1360 `briefNow = { type: "cos-brief-state", state, text, title }`; src/report.html:521-531 handles `cos-host` (hire, runBrief) and `cos-brief-state` (state running). Fix: reuse `cos-brief-state`; do not add `briefRunning`. Keep `cos-host` for host capabilities only.

3. should Today > Day timeline: design presents the timeline as new and replacing the ribbon for today. The ribbon already has a 07:00–20:00 axis, a now line, and past/upcoming logic for today. Evidence: src/today.rs:646 `fn ribbon`, :650-656 axis constants, :695 `now_m`, :728 `past`, :750-755 now line with `cx.now.strftime`, :767 upcoming filter. Fix: state the delta (hire blips, outcome words, collapsed other days) against the existing ribbon, and say the timeline reads `Ctx.now` (today.rs:35, :46 `data["now_ts"]`) so the fixed-now test is possible.

4. should Flows > scan data: `flows::scan(projects, cn, budget)` has no home or workspace parameter. Design says the scan reads `agents::list` "in the business's home". Evidence: src/flows.rs:707 `pub fn scan(projects, cn, budget)`, :712 `scan_with(...)`, callers src/ritual.rs:574 and src/main.rs:760; `agents::list(home)` at src/agents/mod.rs:820 needs `home`. Fix: list the signature change (home through scan and scan_with, both callers, and the test fixtures) in the design's Data section.

5. should Flows > hire-to-bead key: matching uses `spec.source = "bead:<repo>/<id>"`. The writer is apps/desktop/src/lib.rs:1763 `format!("bead:{repo}/{}", b.id)`. The design never says what `repo` is in that string, and `Flow.repo` (src/flows.rs:272) may differ (path, name, or org/name). Also `source` is free text for other hire paths (src/agents/mod.rs:100, :569). Fix: name the exact `repo` value written, the match rule against `Flow.repo`, and the behaviour for a non-matching or malformed source (ignored, not an error). Add a test for it.

6. should Flows > bead states: lanes table lists "failed review / drift" as a bead state. `Bead.status` is a free string (src/flows.rs:162-180). Drift is flow-level (`Flow.drift_unchecked` :276, `Flow.step` errored). Fix: enumerate the `Bead.status` values the lanes and ring map (done, in progress, ready, blocked) and put drift on the flow header/rail, not on a bead box. Confirm `ready` and `blocked` are derived (`Bead.ready`, `open_blockers`) and not stored states.

7. should Shared > reduced motion gate: design says the gate is extended to kit.css, report.html and flows.html. The current gate reads only style.css and checks only the `animation:` shorthand. It ignores `animation-name`, `transition` durations, `@keyframes` blocks, and `element.animate` in JS. Evidence: tests/design.rs:1452-1475 (`read("apps/desktop/ui/style.css")`, `css[i..].starts_with("animation:")`). Fix: say the extension checks (a) every `animation`/`animation-name` declaration, (b) every `transition` with duration over `--motion-fast`, (c) the `<style>` blocks of report.html and flows.html, and (d) the inline glide/swap JS by a textual check for `.animate(` outside a `no-preference` or `reduce` guard. Acceptance 8 depends on this.

8. should Shared > keyframes: `color-mix(var(--warning) 18%)` is not valid CSS. Evidence: design §0 table, `kit-breathe`. Fix: `color-mix(in srgb, var(--warning) 18%, transparent)`.

9. should Shared > shimmer state: design says `stateView("reading" | "refreshing" | "starting")` "gains a shimmer variant". Existing kinds are keys of `STATE` (apps/desktop/ui/states.js:103-124). Gate `every_state_renders_through_state_view_with_an_icon_and_art` (tests/design.rs:1325) requires every kind to have an icon and an art picture in ART. Fix: say whether shimmer is a new kind (needs STATE + art/art.js entry) or a `variant` flag on existing kinds, and which kinds get it.

10. nit Lanes > ring: ring is `role="img"` with a label, inside Board cards that carry buttons (src/flows.html:477, :492). Fix: put the label on the card's accessible name or use `aria-label` on a non-interactive wrapper; avoid a role=img child inside a button.

11. nit KPI ticker: "previous value is the prior KPI point" reads `data["kpi_points"]` (src/kpis.rs:63, :85). With one recorded point there is no prior, so nothing rolls. Fix: state the first-render rule (no prior: show the value, no roll) and that the ticker reads only the last two points for the same kpi.
