1. blocking Semantic ISA, Side-effect inventory (design:234-242) and Taint and sinks (design:259-269): inventory misses sinks that write or kill on the switched triple. (a) Docs POST `/docs/organize` through `cosreport://` calls `save_organize(home)`, writing `<home>/context`; gated only by `X-Cos: docs`. Evidence: apps/desktop/src/lib.rs:114-134; src/docs.rs:854-860, 249-252. Not in the table; only `docs_save` (lib.rs:151-158) is. (b) `agents_record` writes state. Evidence: lib.rs:404-420; src/agents/mod.rs:515-531 (`write_state` at 529). (c) `agents_rejudge` writes state and appends the ledger. Evidence: lib.rs:212-216; mod.rs:498-511 (`write_state` 506, `ledger::append` 508). (d) `agents_list` and `agents_tail` call `agents::list`/`read`, which run `reconcile`: `kill_group` on a dead supervisor's harness (mod.rs:486) and a `state.json` rewrite (mod.rs:492). Evidence: lib.rs:167-176, 437-448; mod.rs:446-494. Design only names this for `businesses()`, but after a switch it runs against the new home. Fix: add a row for each with its VERIFY (business name resolves in the fresh registry; its dirs pass VERIFY(business_dirs)). State that listing reconciles on the switched home. Add a test per row that the write lands under the new home (see finding 13).

2. blocking Long-lived processes and Command `task schedule` (design:24, 143-146): `task schedule BUSINESS=<name>` adds `--business <name>` to the plist arguments, but the plists still set `COS_HOME`, and the design says the plists are unchanged. Resolver step 1 then errors: "--business and COS_HOME both set" (design:110, 279). Every scheduled run for a non-default business exits non-zero. Evidence: launchd/cos.brief.plist:14, launchd/cos.dash.plist:15; Taskfile.yml:187-197 (sed substitutes `@COS_HOME@` from ROOT_DIR); design:145 "the plists are unchanged". Also a non-default triple cannot be expressed in the plist without `COS_WORKSPACE`/`COS_PROJECTS`, which the design never mentions. Fix: the schedule template emits either `--business <name>` with no `COS_HOME`, or the explicit `COS_*` triple, never both. Add the plist and Taskfile changes to the change list. Acceptance: `task schedule BUSINESS=acme` then a launchd-style run writes acme's `out/logs`.

3. should Semantic ISA, Side-effect inventory (design:241): the report handler is listed as writing `<home>/out/report.html`. It does not. The app's report handler calls `report::data` and `render` only. Evidence: apps/desktop/src/lib.rs:85-99; `report::build` (src/report.rs:24-31) is called only from main.rs:371 and pipeline.rs:432, 471, not from the app. Fix: drop the report-handler write from the inventory, or name the CLI/pipeline callers as the writers. Keep the report handler read-only in the test list.

4. should Desktop, App business (design:150-152, 21 of brief): app startup source is undefined. Design says `business` unset means legacy explicit directories (step 2). It does not say what happens with no `settings.json`, a legacy triple plus a registry `active`, or no registry at all. The brief says the app starts on the active business (brief:19-21). Two implementers would differ. Evidence: design:150-152; brief:19-21; apps/desktop/src/settings.rs:44-70 (env, then saved, then defaults). Fix: state the order: `settings.business` if set and present, else legacy fields if present (explicit), else registry `active`, else defaults. State what the header and picker show when the app business has no name (no registry).

5. should Migration (design:137-140) vs brief decision (brief:31-32, "on first run the current triple becomes a business named default, active, with no files moved"): the design has no automatic migration. The registry stays absent until the user runs `cos business add`, the picker lists nothing, and the legacy triple is unnamed. The design does not record this as a change to the user's decision. Evidence: design:137-140, Acceptance 1 (design:332-333); brief:31-32. Fix: either restore first-run migration (write `default` only when the registry is absent and a legacy triple exists) or record the change in Decision and the brief.

6. should Resolver (design:110, 279) vs brief (brief:33, "A COS_* env var still overrides for one command"): the design makes `--business` plus any `COS_*` directory env an error, not an override. Not recorded as a decision change. Evidence: design:110, 279, Acceptance 7 (design:345-346); brief:33. Fix: record the change in Decision and brief, or implement override semantics.

7. should Resolver and bootstrap (design:103-104, 134-139): `add`'s own `--home`, `--workspace`, `--projects` are subcommand args, not resolver inputs; the top-level `Cli` fields are not `global` (src/main.rs:17-26). The design says the empty-registry `default` is written "from this invocation's resolved triple (step 2 or 4)" and does not say whether `add`'s flags count. If they do, `default` becomes acme's triple and the duplicate-home rule (design:137-139) refuses the `add` itself. Evidence: src/main.rs:16-26; design:137-139. Fix: state that `add`'s directory flags are its own arguments and not resolver input; `default` comes from top-level flags, env or defaults only. Test: empty registry, `add acme` (Acceptance 2) writes `default` with the build-clone home and `acme` with its own dirs.

8. should Desktop, state layout (design:150-154, 180-181): `Triple` sits "in the app state next to Settings". If they are separate locks, one command can read `home` before a switch and `workspace` after it, which is a mixed triple inside one window. Evidence: apps/desktop/src/lib.rs:23-29 (`App(Mutex<Settings>)`, `get()` clones one snapshot). Fix: hold `Settings` and `Triple` under one lock, or make `Triple` the only source for paths, and have each command take one snapshot.

9. should Desktop, reload (design:173-176): the reload design writes "the current tab to the URL hash", but no startup code reads a hash. `app.js` reads `location` or `hash` nowhere; its only hash is `reportState.tab` for the iframe (app.js:170, 186-188). Pane state (`ui.pane`, `ui.from`) is not persisted (app.js:23-36, 193-206). Acceptance 4 needs "same tab". Evidence: apps/desktop/ui/app.js:186-206; design:173-176, Acceptance 4 (design:337-339). Fix: specify the hash scheme (top-level tab, Agents pane), the startup read, and add both to the change list.

10. should Acceptance 4 (design:337-339): names a "plan" view. The app has no plan view. Top-level tabs are Today, Agents, Flows, Docs (ui/index.html:18-21). Staff is an Agents pane (ui/index.html:179). Evidence: ui/index.html:18-21, 179. Fix: name the real views (Today for the report, Agents and Staff, Flows, Docs) so the acceptance can fail for the right reason.

11. should Registry, `remove` (design:141): `cos business remove` refuses only the active business. The app business is stored in `settings.json` (design:150) and is not protected, so it can dangle. Startup behaviour in finding 4 is then undefined. Evidence: design:141, 150. Fix: refuse removing any business that a `settings.json` `business` field names, or define the fallback. Add to the ISA violation table and the test list.

12. should Testing (design:298-306): the "two concurrent `use` calls leave a parseable file naming one of them" test passes without the lock. `use` changes only `active`, so one of the two survives whatever happens. Design Risk (design:211) names lost update, and no test catches it. Evidence: design:304-306. Fix: run two concurrent `add` calls with different names and assert both are present, repeated enough times to be a real race.

13. should Testing (design:310-318): nothing asserts that a switch routes writes to the new triple. The ipc test covers `paths()`, the report handler (read-only) and flows. `docs_save`, the docs POST, `agents_spawn`, `agents_record` and `agents_stop` go untested after a switch. Evidence: design:310-315; apps/desktop/tests/ipc.rs:195-219 (existing set_workspace test and `docs_save`); lib.rs:151-158, 363-391, 404-420. Fix: add a test that switches to a second business and asserts `docs_save` writes under its `context`, `agents_spawn` creates its run under its `out/agents`, and `agents_record` writes there.

14. should Testing, env pin (design:292, 155-157, Acceptance 6): the pin reads `COS_*` from process env. The ipc builder takes `Settings` (ipc.rs:107-114; `builder(mock, Some(settings))`), and the design gives no way to inject pinned variables. Setting real env in parallel tests races. Evidence: apps/desktop/tests/ipc.rs:107-114; apps/desktop/src/settings.rs:44-50, 59 (env read directly); lib.rs:522-524. Fix: read the pinned variables once in `Settings::load` and pass them to `builder` as a value, so the test injects them without touching process env.

15. nit Context (design:50-54): the `cli.projects` sites are not all listed. Missing: main.rs:385, 428, 571; the `run()` sites at 330-332 are covered only implicitly. Evidence: src/main.rs:385 (`cli.projects.clone()`), 428 (`flows_cmd(&ws, &cli.projects, ...)`), 571 (`&cli.projects`). Fix: add them. The compiler will flag them once the fields become `Option`.

16. nit Testing (design:302-303): the "CLI and app produce the same strings" defaults test is tautological if both call `cos::business::resolve`. Fix: assert the literal expected strings (`$HOME/Projects`, the canonical build-clone path) for an empty environment.

17. nit Registry (design:88-97): `state::atomic_write` already uses a unique temp name (src/state.rs:554, `.state-{pid}-{nanos}.tmp`), so "widened to take bytes with a unique temp name" should say reuse. Load rules do not say what `active` absent with businesses present means (design:92-94). Fix: state both.

18. nit Resolver (design:103-110): `--business` and `COS_BUSINESS` set to different names is unspecified. Fix: state precedence (flag wins) or make it an error.

19. nit Desktop (design:152-154): `save()` must stop writing `home`, `workspace`, `projects` (design:152) while the legacy fields stay readable. That needs a separate legacy read type or `skip_serializing`. Evidence: apps/desktop/src/settings.rs:12-23, 91-98. Fix: state which.

20. nit Confidence (design:324-328): "Resolver rock" and "Desktop switch rock" are premature while finding 1 (sinks) and finding 4 (startup source) are open. Fix: rate sand until both are resolved.

21. nit Workspace (design:124-126, 277): `state::runtime_dir` refuses a symlinked `.chief-of-staff` (src/state.rs:530-532). The canonical-path rule for the workspace does not say how a symlinked runtime dir is treated. Fix: state the outcome (refused, as today).

22. nit Acceptance (design:332-347): Acceptance 2 presumes `~/biz/acme/repos` exists; `add` requires existing dirs (design:134-136). Acceptance 4 presumes acme has a profile, which switch requires (design:162-163), but no step creates it. Fix: add the precondition steps (`mkdir`, `cos --business acme state init`).

23. nit Launchd (design:24, 143-146): the design never says `cos.brief` and `cos.dash` ignore `active` because they set `COS_HOME` (explicit, step 2). Fix: state it so an implementer does not add a registry read to the plists.
