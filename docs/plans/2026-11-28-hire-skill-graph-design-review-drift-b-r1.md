## Findings
1. blocking `## Built as` item 1 (Codex `skills.config`, S9): a malformed or non-array `$CODEX_HOME/config.toml` silently drops the user's own `skills.config` entries. `codex_config` parses with `.parse::<toml::Table>().ok()` and `.as_array()...unwrap_or_default()`, so a parse failure or a wrong shape yields an empty list. The hire then launches with `-c skills.config=[…]` holding only the hidden names, which re-enables every skill the user had switched off, with no warning and no plan note. This breaks VERIFY-C ("the user's own entries are carried as parsed TOML values") and the fail-safe requirement. A missing file is safe (empty list). A malformed file is not. Evidence: `src/agents/skill_bundle.rs:42-46`; `src/agents/mod.rs:643-648` (`launch` calls `codex_config` and discards the error path); `tests/hiring.rs:856-907` covers only a well-formed file whose one entry is already `enabled = false`, so the malformed case is untested. Fix: `codex_config` returns `Result`. A file that exists but does not read, does not parse as TOML, or has a non-array `skills.config` fails the hire in `launch` before Herdr, as a seed failure does, naming the file and the error. A missing file stays `None`/empty. Add a test with a malformed `config.toml` that asserts no Herdr terminal is created and that the run's error names the file.
2. blocking `## Built as` Semantic ISA, E8 and E11: E8 lists only `state.json` gaining `skills_bundled`. `prepare` also writes `state.skills_hidden` for both harnesses (`src/agents/mod.rs:724` Claude, `:727` Codex), persisted by the `write_state` at the end of `prepare`. No row covers it. E11 lists the Codex `-c` value on the command line but not where that value goes: it is passed as an argv element to `herdr::run` (`src/herdr.rs:226`, `cmd.arg("--").args(l.argv)`) and so leaves the cos process carrying the user's own config entries (including any `path` strings). Whether Herdr retains argv is not verified here (no Herdr source read, no live calls). Fix: extend E8 to name `skills_hidden`, and add an E11 note that the Codex value leaves cos via `herdr::run`, stating whether Herdr persists it. Alternatively, confirm Herdr does not retain argv and record that in the row.

Checked, no finding:
- Prepare-time `project_skills` filter: `hidden_codex` (`src/agents/skill_bundle.rs:58-65`) and `skills::resolve` (`src/agents/skills.rs:445-447`) both exclude the repo's `.claude/skills` and `.agents/skills` names, so a repo skill is never disabled.
- Injection: hidden names pass `valid_name` (`src/agents/skills.rs:25-32`, `[a-z0-9][a-z0-9._-]{0,63}`), and the value is built with the `toml` crate's `Value` (`skill_bundle.rs:53`), so no quote can break out.
- Argv path: `environment` (`src/agents/mod.rs:748-787`) builds argv as separate elements behind `/usr/bin/env`; no shell string.
- Single flight (`src/agents/skill_facts.rs:26-46`, `:141-143`): the guard is an RAII `Flight` held in a local for the whole call, so early returns and panics (unwinding runs `Drop`) remove the home. Poisoned mutexes are recovered with `into_inner`. No path leaves a home marked in flight forever.
- Test pins: every hire test goes through `fake()` or a `setup` that calls it (`tests/hiring.rs:61-63`, `tests/agents.rs:88-90`, `tests/hire_events.rs:502-504`, `tests/judge.rs:75`). `tests/fit.rs:131` uses `SkillsAsk::off()`, which returns before any skill or Prime read (`src/agents/hire.rs:75`). `tests/skills.rs` and `tests/prime.rs` build roots and Prime explicitly. No test found that reads the real `$HOME` skills or the live Prime at 127.0.0.1:3906.

## Carried to Plan
- `tests/skills_cli.rs:53-60` (`cos()`) pins `COS_SKILLS_HOME`, `COS_PRIME_URL` and `COS_RUN_ID`, but not `CODEX_HOME`. The child inherits the developer's `CODEX_HOME`. `cos skills show/ls` does not reach `codex_config`, so no current leak, but pin it to keep the isolation uniform.
- `tests/fake_herdr/mod.rs:52` pins `COS_PRIME_URL` to `http://127.0.0.1:9/mcp`. That is a loopback address, so VERIFY-U admits it and the client attempts a connect (refused by the kernel). The design calls the pinned value "refused"; either reword the design or pin a URL VERIFY-U rejects, so no socket is attempted.
- Design §2 (`docs/plans/2026-11-28-hire-skill-graph-design.md` lines 196-202) still says "one call in flight per process". `## Built as` item 2 changed it to per home. Update the §2 text so the approved body and the Built-as note agree. Per home means one desktop process polling several businesses can hold one Prime call per business at once, each bounded to 2 s.
- `tests/hiring.rs:856-907` asserts `all(enabled == false)` over entries whose only user entry is already disabled, so the assertion holds trivially. Add a user entry with `enabled = true` and assert that the hidden entry for the same name comes after it (last wins), and a case with a non-array `skills.config`.
- `codex_config` falls back to `$HOME/.codex/config.toml` when `CODEX_HOME` is unset (`skill_bundle.rs:37-41`), and `Delivery` reads it at `launch`, not at `prepare`. A config edited between plan and launch changes the override silently. Record the read time in the run's `state.json`, or document it.
