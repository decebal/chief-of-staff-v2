1. blocking Context, Fixes taken first, Testing: the design calls `pipeline.rs:120` and `:184` "live bugs" that read the profile from home. Every caller passes the workspace: `dates_in(&self.workspace)` at pipeline.rs:344, 360, 388, 408; `cover_every_source(&mut brief, &self.workspace, …)` at pipeline.rs:459. The parameter is misnamed `home`, but the read is correct today. The "fails before the fix" test cannot fail. Evidence: pipeline.rs:119-120, 183-184, 344, 360, 388, 408, 459. Fix: reclassify the two sites as rename-only. Drop "live bug" from Context (design:30-31) and Fixes (design:112-116). Replace the fail-first tests with a test that drives `Config` with home ≠ workspace and asserts the workspace profile is used. That test passes before and after, and is labelled as characterisation.

2. blocking Resolver (design:72-77): precedence is per directory, so `COS_HOME` (step 2) beats `--business` (step 3). `COS_HOME=/a cos --business acme brief` yields home=/a with acme's workspace and projects, a mixed triple. The brief says "a business is all three directories" (brief:23). The same happens in the app: a pinned `COS_HOME` survives `switch_business`, and design:96 only shows a note. Evidence: design:73-75; main.rs:18,22,25 (clap `env` on home, workspace, projects); settings.rs:48-58 (env wins over saved). Fix: when a business is selected by `--business`, `COS_BUSINESS`, or the registry `active`, the business supplies all three directories. Env and flags override only when set explicitly, and the resolver reports the source of each directory. The app refuses `switch_business` while any of the three is env-pinned. The precedence table in Testing (design:191-193) must assert no mixed triple.

3. blocking Desktop `businesses()` (design:97-98, 107-108, 208-209): "reconcile left lazy" is not available through `agents::list`. `list` calls `read` for every id, and `read` always calls `reconcile`. For an agent whose supervisor is dead, `reconcile` runs `proc::kill_group` and rewrites that agent's `state.json`, in another business's home. Counting live agents for the picker and the badge therefore mutates other businesses. The badge's refresh trigger is also unspecified (`agents-changed` fires every 700 ms, lib.rs:481-499). Evidence: src/agents/mod.rs:446-452 (`read` → `reconcile`), 455-464 (`list`), 469-494 (`reconcile`: 486 `kill_group`, 492 `write_state`); lib.rs:477-480 (the existing comment: `agents::list` is "too dear per tick"). Fix: add a read-only count, e.g. `agents::count_live(home)`, that reads `state.json` and checks supervisor liveness without writing or killing. Name the refresh trigger (picker open, plus `agents-changed` throttled). Test: `businesses()` leaves another home's `state.json` byte-identical when its supervisor is dead.

4. blocking Semantic ISA, Side-effect inventory (design:137-145) and Taint (design:159-167): the inventory is incomplete.
   (a) `switch_business` writes `active` to the registry (design:99). The inventory row lists only "add, use, remove, migrate" (design:141).
   (b) Because `active` is what unflagged CLI runs read, the app picker changes which business `cos.brief.plist` runs against. That job passes no `--business` (launchd/cos.brief.plist:14 sets only `COS_HOME`). Nothing in the design says so.
   (c) The switched triple feeds sinks the taint table omits: `docs_save` writes `<home>/context` (lib.rs:151-158, docs.rs:251,264); `agents_spawn` creates worktrees and a detached supervisor under `s.home` (lib.rs:363-391, esp. 386); `agents_stop` kills process groups (lib.rs:423-426); `agents_clean` removes worktrees (lib.rs:429-431); report build writes `<home>/out/report.html` (report.rs:28-31). None has a VERIFY.
   Evidence: as cited. Fix: add a row for `switch_business` (writes `active`) and one for the reconcile behaviour of `businesses()`. Add those sinks to the taint table, each with its VERIFY (the business name resolves through the freshly loaded registry, and its triple passes VERIFY(business_dirs)). State the `cos.brief` consequence and either pin it with `--business` in the plist or refuse switching while that job exists.

5. blocking Desktop cache reset (design:103-106): the list is incomplete, and it misses the stale-response race.
   - Race: `refreshAgents` has an in-flight guard, and a late result from the old business is assigned to `ui.agents` (app.js:242-267, esp. 249). `refreshStaff` (269-289) and `feed.pull` (673-692) also write late. Nothing in the design tags responses with a business generation, so an old-business result can render after `resetForBusiness()`.
   - Missing from the list: `ui.roles`, `ui.defaults`, `ui.scores` (overwritten only on success, app.js:276-285); `#policy-note` (279-281); `hire.plan`, `hire.edited`, `hire.seq` and `fitTimer` (876, 967-991); `feed.pulling`, which makes a new pull return the old promise (674); `ui.pane` and `ui.from` (193-199); `reportState.y` (170-179).
   - `loadRepos` appends options and never clears them (app.js:878-882); the design says to reset it, but not how.
   Evidence: as cited. Fix: keep a business generation counter in `ui`. Every async handler captures it and drops its result when it has changed. Enumerate the full reset list above. State how `docs-frame` and `flows-frame` are reset (set `src` to `""`, then reload). Test: a switch while `agents_list` is pending leaves no old-business rows.

6. should Taint (design:161-167): sources omit `settings.json`'s `cos` field, which is executed as the supervisor (settings.rs:20-22, 68, 75-89; lib.rs:365). The symlink rule "not a symlink to elsewhere once canonicalized" (design:166) is neither deterministic nor the rule the code uses. `state::runtime_dir` refuses any symlinked `.chief-of-staff` (state.rs:527-531). Fix: add the `cos` binary field as a source with its own VERIFY (an executable file that is the cos binary). Replace the symlink phrase with "`runtime_dir` passes and canonical path equals the stored path".

7. should Testing (design:189-201): (a) "Settings literals gain `#[serde(default)]` fields so the existing tests compile" (design:198-199) is wrong. Serde defaults do not affect struct literals. The literals are at apps/desktop/tests/ipc.rs:107-113, 295, 441. (b) ipc.rs:195 calls `set_workspace`, which the design removes (design:100), and the design does not say to update it. (c) `builder(mock, Some(settings))` bypasses `Settings::load` (lib.rs:503-507, 521-524), so the registry path is never exercised. The design must say how IPC tests inject a registry. `COS_BUSINESSES` is process-global across parallel `#[test]` functions. (d) "atomic write leaves the old file on a failed write" names no injection point. (e) The tests named do not catch blocking items 3, 4 and 5 (no test of reconcile side effects, of stale responses, or of the taint sinks). Fix: state each of these, and add the named tests.

8. should Migration (design:61-63) vs Alternatives (design:120-122): migration reads "app settings" for the CLI, but design:120-122 rejects the CLI reading the app's `settings.json`. The design does not say which binary migrates, or what "the first command that needs it" means. Acceptance 1 (design:213-214) covers only `list`. Fix: name the migrating binary and the commands that trigger it. Say whether the CLI reads `settings.json` for migration only.

9. should Defaults (design:67-81, 22-26): the two defaults disagree. The app's home is `CARGO_MANIFEST_DIR/../..` and is not normalised (settings.rs:26-28, absolute at :51), so the string contains `apps/desktop/../..`. The CLI's home is `CARGO_MANIFEST_DIR` (main.rs:883-885). The projects fallback differs: the app uses `$HOME/Projects` or home (settings.rs:55-58); the CLI uses `home_dir().join("Projects")`, which is the relative `Projects` when `HOME` is unset (main.rs:25, 875-879). Fix: the resolver owns the defaults and canonicalises them. Add a test that the CLI and the app produce identical strings from an empty environment.

10. should `add` rules (design:85-87 vs 166): `add` prints a hint and succeeds when `profile.json` is missing. The STORE(registry) check (design:166) requires `profile.json`, which refuses the write. The design also does not say what `add` does when the name exists (overwrite or refuse). Fix: choose one. Refuse an existing name unless `--replace` is given.

11. should Resolver threading (design:79-81): the code reads `cli.home`, `cli.projects` and `cli.workspace` at main.rs:330, 348-349, 370-371, 383, 392, 396, 401, 512, 843. The design does not say whether the resolved triple overwrites the `Cli` fields or travels in a new struct. Making `home` and `projects` `Option` also changes every site. Fix: state that `resolve` returns a `Triple`, and that `run()` takes it. Name the sites that change.

12. should Registry concurrency (design:56-60, 99): the CLI and the app both write `businesses.toml`. The temp file name is fixed, so two writers share `businesses.toml.tmp`. The design has no lock and no read-merge-write. The app does not watch the registry (lib.rs:481-499 watches only report and agents). Fix: take a lock file for each write, re-read the registry inside the lock, and name a unique temp file. State when the app re-reads (on picker open is enough).

13. should Registry format (design:56-63, 141, 173-175, 182): the `.bak` step is in the inventory (design:141) and in the test matrix (design:182), but not in the write sequence (design:58-60). The violations table has no row for `active` naming an absent business (hand edit), and "`.bak` named" (design:175) is unclear. Fix: add `.bak` to the write sequence, add the missing violation row (refuse, or fall back to `default` with a message), and rewrite the unclear phrase.

14. should Desktop (design:109-110): "A brief or ask in flight keeps writing to the business it started in; the status line says which" names a surface that does not exist. The app has no brief or ask command (lib.rs:528-546) and no status line. Fix: delete the sentence, or restate it for `agents_spawn`, the operation that actually runs in the background.

15. should Scope (design:92-110, 119-125): the launchd jobs and Taskfile are not in the change list. `launchd/cos.dash.plist:15` and `launchd/cos.brief.plist:14` set `COS_HOME`. Taskfile.yml:194 substitutes `@COS_HOME@` into the plists. `.claude/agents/tactician.md:21` tells agents to read "`@COS_HOME@`" elsewhere, and Taskfile.yml:48 substitutes it at install. Those agent files cannot follow the active business. Fix: add the plist and Taskfile changes to the design, and say whether the agent files are in or out of scope.

16. nit Confidence (design:203-209): "Registry, resolver, CLI: rock" is premature while items 2 and 10 are open. Fix: rate the resolver `sand` until those are settled.

17. nit Registry (design:64-65): "0.8.2 or 1.1.8, whichever the lock resolves without a new crate" leaves the choice to each implementer. Cargo.lock has both (Cargo.lock:3734, 3746). Fix: name one.

18. nit Desktop (design:103): Enter with zero matches is undefined. The binding is a slug (design:156-157), so the picker must not pass free text. Fix: state that Enter with no match does nothing.

19. nit Docs: CLAUDE.md:31, docs/usage.md:458 and apps/desktop/README.md:8 describe `COS_WORKSPACE`/`COS_PROJECTS` as the way to set the workspace. Fix: add the doc updates to the change list.

Checked and correct: CLI line refs (main.rs:16-45, 327-335, 42-44); app refs (settings.rs:45-47, lib.rs:59-80, app.js:93-132, tauri.conf.json:22 `script-src 'self'`); `set_workspace` as the only runtime switch (lib.rs:59-80); the misnamed-parameter sites track.rs:58-72,192, context.rs:72-74,203-248, main.rs:775 (all receive the workspace); the agent paths (mod.rs:256-258, slots.rs:40-41, 68-69); the absence of `ui/command.js` and of any vendored component JS (ui/ listing; vendor/README.md).
