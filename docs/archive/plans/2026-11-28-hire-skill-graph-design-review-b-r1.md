1. blocking §3 Planning / context/agents.json: design adds top-level `skills.roots` and `skills.unreviewed` to `context/agents.json` but never adds the field to `Policy`. `Policy` is `deny_unknown_fields`, and `policy::load` on a parse error returns `Policy::default()` (roles, repos, defaults all dropped; only `note` set). Every file that carries `skills` loses its whole staff policy. Evidence: `src/agents/policy.rs:109-110` (`#[serde(deny_unknown_fields)]` on `Policy`), `policy.rs:137-144` (`unwrap_or_else(... Policy { note, ..Policy::default() })`). Fix: add `#[serde(default)] pub skills: Option<SkillsPolicy>` to `Policy` (`policy.rs:110-126`) and a `tests/hiring.rs` case: a file with `skills.roots` keeps its `roles`.

2. should §4 Delivery, E6: design puts the Codex "Skills for this work" block in `hire::plan`. `plan()` takes no harness (`src/agents/hire.rs:63-69`); harness arrives only in `Run` (`hire.rs:168-177`) consumed at `Plan::request` (`hire.rs:181`). Placing it in `plan` makes `Plan.prompt` Codex-specific for every harness. Fix: build the block in `Plan::request` (has `run.harness`) or in `harness::argv` from `Spec.skills`; say which, and drop "`hire::plan`" from E6 (design line 235).

3. should §4 Delivery: "under the same step deadline as `seed.rs` (300 s)". `STEP_DEADLINE` is per child: `seed.rs:22` constant, applied per `proc::run` call at `seed.rs:126`. One `cp -Rc` per picked skill gets its own 300 s, so N skills have no bound for the step. Process-ownership rule: one deadline per operation. Also design says `clone_cmd` is reused, but it is private (`seed.rs:147-155`, `fn clone_cmd`). Fix: one `proc::Deadline` (`src/proc.rs` ~50-90) across the whole bundle step, stated as its own budget; make `clone_cmd` `pub(crate)`.

4. should §4 / S3 / E4: `cp -Rc <canonical>` copies the whole skill tree, symlinks included. `~/.agents/skills` is "many symlinks into project checkouts" (design line 51). VERIFY-B checks only `SKILL.md` existence and its sha256 (line 273-277); scripts, references and in-tree symlinks are neither hashed nor confined. A symlink inside a bundled skill can point outside every root, and "digest per skill" (brief line 31) covers one file. Fix: copy with symlinks refused (or dereferenced inside the root only), and record a digest over the sorted file list of the copy, not `SKILL.md` alone. Add the symlink case to the S3 matrix row (line 301).

5. should §2 `read_graph` / §3 planning: no negative cache. The 30 s reuse (line 155-157) applies only after a successful read; on error the design marks `stale` and writes nothing (line 126-127). `app.js:1215-1217` fires `runFit` 150 ms after each input, and each `agents_fit` calls `plan` (`apps/desktop/src/lib.rs:1414`). With Prime slow, each fit check blocks up to the 2 s call deadline (design line 106), and the stale-seq guard (`app.js:1230`) does not stop the Tauri command from running. This is the per-keystroke pile-up the process-ownership rule names. Fix: write `last_failed_at` into `graph.json` and skip the Prime call for 30 s after a failure; state it in §2 and in Acceptance 2.

6. should §2 Read, cache file: "atomic replace" (line 126) with no temp-name rule. The desktop app and `cos agents spawn` both write `out/skills/graph.json` (design line 124-127, 286-289 recovery), so two writers can share a fixed `graph.json.tmp`. Evidence: design line 126. Fix: temp name unique per writer (`graph.json.<pid>.<nanos>`), then `rename`; test in `tests/prime.rs` with two concurrent writers.

7. should ISA VERIFY-U / E1: "`host` resolves only to loopback addresses" requires a DNS lookup for any non-literal host. That lookup is a network side effect not in the inventory (E1 lists only the socket), and the matrix row (line 299) with `http://example.com/mcp` performs it. Fix: accept only a literal `IpAddr::is_loopback` host or the string `localhost`; refuse any other DNS name without resolving it; add the DNS-name case to the S1 row as "no lookup, no socket".

8. should §2 Resolve step 4 / `skills.unreviewed` default `"on"` (design line 148): with the default, every unreviewed global skill (about 230 across roots, brief line 9-10) stays on for every Claude hire until curation. The brief's stated problem (brief line 11-16) is unsolved on day one, and Acceptance does not test it. Fix: state the day-one behaviour in Goal, and add an acceptance row: with `unreviewed: on`, the hire's `hidden` list excludes unreviewed skills and the plan says how many stay on.

9. nit §3 / Testing: `hire::plan` gains a parameter, so its callers change: `src/main.rs:987`, `src/mcp.rs:295`, `apps/desktop/src/lib.rs:1414`, and tests `tests/fit.rs:125`, `:212`, `:348`. Design lists none of the test call sites. Fix: name them in §3 so the signature change is not discovered at compile time.
